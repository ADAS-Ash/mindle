**Mindle 2.1.0** is the collab release. Annotations grew from a single-user margin tool into a multi-author review surface, with identity, status, assignment, labels, threading, and an agent-facing MCP server — all still stored locally in the same per-document `.mindle.json` sidecar, no account or backend involved. Alongside collab, the release lands the long-promised remote-URL reading, word-level diff inside the reload-review surface, and an opt-in beta-update channel for future RCs.

If you've been on the `2.1.0-rc*` train, this is the same code as `rc7`. If you're upgrading from `2.0`, everything below is new.

> 💚 A huge thank-you to [**@ADAS-Ash**](https://github.com/ADAS-Ash) — the team-collaboration foundation in this release ([PR #17](https://github.com/nonatofabio/mindle/pull/17)) is their work. Status/assignee/labels, `IdentityManager`, the collaborator registry, identity-colored highlights, the debug console, the `⌘⇧K` shortcut, and the `resolve` / `assign` / `get_collaborators` MCP tools all landed there. Everything in this release sits on top of that.

## Collaboration on annotations

Annotations now carry author, status, assignee, labels, and a per-message thread — stored in the existing sidecar so old files decode unchanged, and any teammate with the same `.md` + `.mindle.json` pair on a shared drive (Dropbox, iCloud, git) becomes a co-author.

- **Identity.** A small badge at the top of the sidebar (click to set your alias + display color). Every save auto-registers you into the document's collaborator registry, so the next person to open the file sees your annotations stamped with your name.
- **Status pills.** Each card shows **OPEN / RESOLVED / WONTFIX** with one-click Resolve / Reopen. Replaces the "delete the annotation when you're done with it" workflow.
- **Assignment.** Hand an annotation to anyone in the registry — they see it filed under their name when they open the doc.
- **Labels.** `question`, `blocker`, `nit`, `todo`, `suggestion` — preset chips on the card. Triage at a glance.
- **Threading.** Reply inline under an annotation; the thread renders as a stripe of messages with per-author color cues so you can scan a long back-and-forth without losing track of who said what.
- **Identity-colored highlights.** The reader-pane mark tints with the author's registered color (CSS `color-mix` against the current theme, so the tint reads on light, sepia, and dark). Your highlights in your color; a teammate's in theirs.
- **Sidebar parity.** The card dot, the passage stripe, the per-message thread stripe — all consult the same registry, so a multi-author doc is legible from the sidebar alone, not just the reader pane. Aliases are shown next to the timestamp, truncated to 8 chars when long.
- **Per-tab registry.** Each open document carries its own collaborator state. Switching tabs between two docs with different authors restores each document's own colors and never bleeds.

## Multi-document tabs in a single window

`File → Open` now opens documents as tabs within the existing window instead of stacking new windows. Each tab carries its own annotations, scroll position, theme, font scale, and collaborator registry; switching is instant because state is kept in memory.

## Open remote URLs

`File → Open URL…` (`⌘⇧L`) fetches any `http(s)` URL pointing at raw Markdown — typically a GitHub raw link — and opens it as a tab. The URL is the tab's identity, so re-opening the same URL returns to the existing tab instead of re-fetching.

Annotations on URL documents persist to `~/Library/Application Support/Mindle/url-sidecars/<hash>.mindle.json`, keyed by a stable hash of the URL string. Highlight a passage on a remote README once, close the tab, come back tomorrow — the annotations come back with it. If the clipboard contains a URL when you open the prompt, it auto-fills.

## Word-level diff inside line chunks

The diff-on-reload review surface (track-changes between the on-disk version and the version you last accepted) used to strike through and tint *whole* changed lines, leaving your eye to hunt for the actual delta. It now runs a second pass at word granularity: only the removed words are struck inside the red block, only the added words are underlined inside the green block. The line-level tint stays as context. Works inside fenced code blocks too — a `print("hello")` → `print("test")` keeps its monospace styling and highlights just the word change.

## Agent-facing MCP server

Mindle now exposes a Model Context Protocol server over a local Unix socket. The bundled `mindle-mcp` helper proxies tool calls from any MCP-aware agent (Claude Code, etc.) into the running app's state — read-only for "what's open / what's annotated," and write for thread participation and triage.

| Tool | Use |
|---|---|
| `list_open_files` | Every file currently open in Mindle, across windows and tabs. |
| `get_annotations` | Every annotation on a given open file. |
| `create_annotation` | Open a new annotation anchored to a passage (agent-authored). |
| `comment_on_annotation` | Reply in an annotation's thread without dismissing it. |
| `clear_annotation` | Mark an annotation done. |
| `wait_for_annotation_event` | Long-poll for the next user event. |
| `resolve_annotation` / `assign_annotation` | Triage from the agent side. |
| `get_collaborators` | List participants on a document. |

The wire protocol on the socket is length-prefixed JSON — not MCP itself — so other tools can speak it without an MCP framework, and the agent has its own filesystem tools for writes that don't need to round-trip through Mindle.

## Beta channel for release candidates

Mindle's auto-updater grew a second channel. Pre-release tags (`v2.1.0-rc1`, future RCs) are delivered only to users who've opted in via **Mindle → Include Pre-release Updates**. Stable releases remain visible to everyone. A custom semver comparator ensures `2.1.0-rc7 < 2.1.0` so beta testers cleanly upgrade to the stable build now.

The About panel now shows the full pre-release version label (e.g. `2.1.0-rc7` instead of `2.1.0`) so beta testers can tell which build they're running.

## Quality of life

- **Collapsible YAML frontmatter.** `---`-delimited blocks at the top of a file collapse behind a small **▸ YAML FRONTMATTER** chevron. Click to inspect. PDF export force-opens them so the printed document still contains the metadata.
- **Reliable highlights on every selection.** `⌘⇧H` and `⌘⇧N` used to read selection state from a 150ms-debounced cache, so a fast select-then-hotkey would either beep silently or anchor to the previous selection. The hotkey path now probes the live selection at activation time, and prefix/suffix anchoring derives from the selection's actual position rather than the first `indexOf` occurrence — so highlights on repeated text land where you actually selected.
- **Debug console** (`⌘⇧D`) — a floating dev window streaming annotation lifecycle events; handy when iterating on collab.

## Three multi-author fixes from rc7

- **#18 — Canonical-path MCP lookups.** `list_open_files` was returning `/private/tmp/foo.md` (Foundation's canonicalisation) while the open-tab store keyed off the raw `/tmp/foo.md` URL the user opened with, so every other MCP path-keyed call was rejected as "file not open." Both sides now normalise via `resolvingSymlinksInPath()`.
- **#19 — External sidecar watcher.** Each open tab now also watches its `.mindle.json` sidecar. A teammate pushing a change to a shared folder, a `git pull`, another Mindle instance — any external edit gets pulled in live, without close-and-reopen. Self-writes are suppressed by a 750ms guard so the FSEvents echo from our own save doesn't loop.
- **#20 — Per-tab collaborators.** The collaborator registry is now per-`DocumentTab`, snapshotted on switch-out and restored on switch-in. Switching between two docs with different authors no longer bleeds colors between tabs.
