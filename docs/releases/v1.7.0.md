## 🪶 The MCP collaboration loop

Mindle becomes a parallel chat surface. You annotate a passage; an agent on the other side of Mindle's MCP server picks it up automatically, reads the file context with its own tools, posts a reply in the annotation's thread (or edits the file and clears the annotation), and waits for your next note. The conversation lives in the document, anchored to the passages that prompted it.

### What landed

- **Annotation threads.** Each annotation now carries a thread of messages — user and agent each authored. The card grows a single-column transcript with author-keyed stripes (gray for agent, accent for you) and an inline Reply box.
- **Agent-authored annotations.** An agent can open a fresh annotation on any span of the file ("does this paragraph read better?") and you can reply in its thread the same way you reply to your own.
- **Ambient watch.** A long-polling MCP tool — `wait_for_annotation_event` — lets an agent run a loop: the user annotates, the agent wakes, addresses it, waits again. Pure MCP, so this works in any client (Claude Code, Codex, Cursor, custom). The agent's own writes are filtered out via a per-helper UUID so it never wakes itself.
- **Keep All / Revert All banner.** Sticky bar at the top of any in-flight diff with bulk-action buttons. The inline per-chunk Keep/Revert stays for granular review; the banner is the path for "agent rewrote eight paragraphs and they all look good."

### Polish that came out of dogfooding

The MCP tools shipped with rough edges that real use immediately exposed. A short tour of what we caught and fixed:

- **Reply focus stability.** The reply textbox now lives in a custom `NSTextView` wrapper that owns its first responder explicitly — sibling-annotation mutations re-render the SwiftUI tree all they want and your cursor stays put.
- **Auto-scroll to new annotations.** ⌘⇧N opens the sidebar if it was closed and scrolls the new card into view; no more "where did it go?" on long files.
- **Race-free created events.** A new annotation now surfaces to watchers when you commit the note, not the instant the editor opens — agents see the finished question, not "What ".
- **Crash hardening.** Every MCP socket sets `SO_NOSIGPIPE` so a dead helper can never bring Mindle down via a stray `write()`.
- **Return / Shift+Return.** The annotation editor now treats Return as commit (Done) and Shift+Return as newline — the universal short-note convention.

### Compatibility

- Existing sidecars decode unchanged. The new `author` and `thread` fields on `Annotation` are optional and only serialise when populated.
- All v1.6 tools (`list_open_files`, `get_annotations`, `clear_annotation`, `comment_on_annotation`, `create_annotation`) keep working. Three new tools surface alongside: `wait_for_annotation_event`, plus the agent-authored-annotation flow has the existing `create_annotation` as its handle.

### Setup

If you've already registered `mindle-mcp` with Claude Code, the new tools appear automatically after a Claude Code restart. If you haven't:

```bash
claude mcp add mindle /Applications/Mindle.app/Contents/MacOS/mindle-mcp
```

Then ask your agent "watch my Mindle annotations and answer them" — and start annotating.
