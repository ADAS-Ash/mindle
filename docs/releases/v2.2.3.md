**Mindle 2.2.3** — finishes the annotation-card overlap fix that v2.2.2 only half-resolved.

## What's fixed

### Action row no longer paints over the body on wrapped annotations

v2.2.2 added the `sizeThatFits` hook so SwiftUI asks for the wrap-aware host height before placing siblings. That fixed the *first* line of overflow, but cards with 5+ lines of body still had the **OPEN / Resolve / Assign** row paint over the bottom of the text. Root cause was the `maxLines` clamp inside the host's height measurement — it multiplied `defaultLineHeight` by the line count, but `defaultLineHeight` is the font's typographic line height and doesn't include the inter-line spacing `NSTextView` applies during real layout. So `4 * defaultLineHeight` always reported a smaller height than 4 rendered lines actually take, the host got sized for ~4 lines but the text view painted ~5, and the next sibling landed on top of the overflow.

The measurement now walks actual line fragments from the layout manager and takes the bottom of the Nth one as the precise clamp height. Plus the host's bounds get `clipsToBounds = true` as a defensive backstop — even if a future layout race produces a 1-pixel discrepancy, the overflow stays inside the card's body region instead of bleeding into the action row.
