> 🧪 **Release candidate.** Hotfix on top of rc3.

## What's fixed

### OpenDyslexic now actually swaps the font

The `ReadingFont` enum's `.openDyslexic` case took the Swift default rawValue, which preserves the case name verbatim — so `mindleSetReadingFont("openDyslexic")` got written into the page as `data-reading-font="openDyslexic"` (camelCase). The CSS selector was `html[data-reading-font="opendyslexic"]` (lowercase), and CSS attribute-value matching is case-sensitive by default — so the rule never fired, and selecting **View → Reader Font → OpenDyslexic** in rc3 silently did nothing.

The enum's raw values are now pinned explicitly to the lowercase strings the CSS selectors expect, so JS/CSS round-trip matches at every site that uses this pattern.
