> 🧪 **Release candidate.** Final RC before v2.2.0 stable. Closes the typography backlog (reading width + OpenDyslexic + Bionic Text), completes the v2.2 reactions story with agent-side writes, and lands [@ad-cqc](https://github.com/ad-cqc)'s annotation-text-selection PR.

## What's new

### Three reading-width stops

The reader pane has always been a fixed 680px column — typography-recommended for line length, but it left big displays mostly blank. [Issue #27](https://github.com/nonatofabio/mindle/issues/27) by [@ad-cqc](https://github.com/ad-cqc). New under **View → Reading Width**:

- **Narrow** — 680px (the v2.1 default).
- **Medium** — 920px.
- **Wide** — 1240px.

Direct shortcuts `⌘1` / `⌘2` / `⌘3`. The choice persists per-document in the sidecar (older sidecars decode cleanly without a width field — they get Narrow as before).

### OpenDyslexic font

Bundled, offline, no telemetry. [OpenDyslexic](https://opendyslexic.org/) is a free typeface designed to reduce letter-swap confusions; under **View → Reader Font** you can switch the reader pane between the default serif stack and OpenDyslexic. Code blocks intentionally stay monospace either way — OpenDyslexic isn't fixed-width, and code mis-aligns inside it.

Bundled under SIL OFL with attribution in `Resources/web/vendor/opendyslexic/LICENSE.txt`. Choice persists per-document.

### Bionic Text rendering

[Issue #28](https://github.com/nonatofabio/mindle/issues/28). Toggle under **View → Enable Bionic Text** wraps the first ~half of every word in `<strong>` so the eye has more anchors when scanning long prose. Skips code blocks, headings, links inside `<kbd>`, and runs that are already bold (no double-bolding).

Composes with whatever font and theme are active — works in OpenDyslexic + Wide + Dark, and any other combination.

### Agent-side reactions over MCP

The agent-write half of v2.2's reactions story, deferred from rc2 to give the human side a few days of real use first. New MCP tool:

```
react_to_annotation(path, id, kind, message_id?)
```

Where `kind` is `+1` / `heart` / `laugh`. Calling twice with the same kind toggles it off. With `message_id`, the reaction attaches to a thread message instead of the annotation. The tool description guides agents to use it when a written reply would be overkill — acknowledging the user's note, agreeing with a thread message, or signaling "got it, continuing" without a full reply card.

### Selectable text in annotation cards

Closes [#29](https://github.com/nonatofabio/mindle/issues/29). Reported and fixed by [@ad-cqc](https://github.com/ad-cqc) in [PR #30](https://github.com/nonatofabio/mindle/pull/30). Text inside an annotation card or thread message was previously unselectable: `Text(...).textSelection(.enabled)` doesn't survive the sidebar's per-mutation re-render (every store change rebuilds every card via `ForEach`, dropping the in-flight drag selection). The fix replaces those `Text` views with a new `SelectableText` `NSViewRepresentable` that owns its `NSTextView` across SwiftUI rebuilds and computes a wrap-aware `intrinsicContentSize` for self-sizing layout. ⌘C now copies; drag-select holds even when a sibling agent reply arrives mid-drag.
