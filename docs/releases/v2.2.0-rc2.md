> 🧪 **Release candidate.** Beta-channel update on top of rc1.

## What's new

### Open from Clipboard

Mindle's `Open URL…` uses an unauthenticated `URLSession`, so any link behind a sign-in (internal GitLab raw views, Confluence pages with the markdown plugin, vendor doc sites you're SAML-SSO'd into) doesn't render — Mindle can't see what your browser sees. Rather than reinvent the browser, **File → Open from Clipboard** (`⌘⇧V`) lets you carry the bytes across by hand: copy the raw Markdown from the source where you're already authed, paste it into Mindle.

The pasted document opens as a tab keyed `clipboard:///<contentHash>` and persists annotations to a local content-addressed sidecar in `~/Library/Application Support/Mindle/clipboard-sidecars/`. Re-pasting the **identical** text — same trimming, same content — activates the existing tab with its prior annotations attached. Different content produces a fresh tab; the original keeps its history.

Tab titles render as `Clipboard · <hash-prefix>` so the strip stays scannable. The v2.1 sidecar watcher still applies, so two open Mindle windows pasting the same content sync each other's annotations through the same plumbing as shared-folder collab. Agents (`list_open_files`) only see real on-disk paths — content-addressed pseudo-URLs are filtered out because there's no path an agent could refer back to.

Auth-walled SPAs and JS-rendered pages still aren't a fit for this approach — those need the WKWebView-backed fetcher with persistent cookies, which is on the v2.3 list.
